## Key Design Decisions

### 1. Telegraph-Style Brevity in Feedback
Following the national language design system's universal grammar rules, feedback messages use concise phrasing:
- "Previous: SIGN | Next starts with: U" (not "The previous word was...")
- "Not quite! Think: 'STOP' + 'S___'" (not "That's not quite right, try thinking about...")

### 2. Emotional Design Integration
Applied Don Norman's three levels throughout:
- **Visceral**: Clean color scheme, smooth animations, appealing Ruut character
- **Behavioral**: Instant feedback, clear affordances, forgiving input (typo tolerance)
- **Reflective**: Streak system creates narrative of skill growth, star ratings acknowledge achievement

### 3. Story Integration Philosophy
Following PRD guidelines for "light touch" narrative:
- NPC dialogues are brief (3-5 seconds)
- Always skippable (tap to dismiss)
- Never gate progression
- Add flavor without interrupting flow
- Rotate messages to avoid repetition

### 4. Self-Contained Architecture
Single HTML file approach chosen for MVP phase:
- Easy to share and test
- No deployment complexity
- Cross-platform compatibility
- Quick iteration cycles
- Later can port to Phaser 3 + Vite stack

## Technical Debt & Considerations

### Current Limitations
1. **Standalone HTML Architecture**: Fine for MVP, will need migration to Phaser 3 for production
2. **Embedded Word Chains**: Only 3 chains; production needs data-driven system with 3,000 levels
3. **No Persistence**: Game state doesn't save; need Supabase integration for production
4. **Simple Animations**: CSS-based; production may benefit from Phaser's animation system
5. **No Audio**: Silent prototype; production needs SFX and music

### Non-Issues (By Design)
- Single file architecture: Intentional for MVP shareability
- Limited content: MVP scope, not production scope
- No multiplayer: Phase 1 focus on core solo mechanic
- No power-ups: Deferred to Phase 2 per PRD

### Future Considerations
- **Asset Optimization**: When moving to Phaser, implement texture atlases
- **Lazy Loading**: 120 lands in 12 groups for memory efficiency
- **Object Pooling**: For particles and animations at scale
- **Performance Monitoring**: Track 60fps maintenance on mid-range devices

## Lessons Learned

### What Worked Well

1. **Agent-Driven Development**
   - game-dev-planner with Gemini + Playwright proved highly effective
   - Single agent delivered production-quality work in 2 hours
   - Playwright testing caught issues before human review

2. **PRD-First Approach**
   - Clear PRD (WordRun_PRD_MVP.md) enabled autonomous implementation
   - Agent didn't need clarification questions
   - Scope was well-defined and achievable

3. **Emotional Design Integration**
   - Research-backed timing targets (from emotional-design-research-report.md) created polished feel
   - Microinteraction timing made prototype feel premium despite MVP scope
   - Character personality emerged naturally from animation variety

4. **Self-Contained Prototyping**
   - Standalone HTML file enabled rapid testing and sharing
   - No deployment complexity allowed focus on gameplay
   - Easy to iterate and version

### What Could Be Improved

1. **Mobile Device Testing**
   - Browser testing is good, but actual mobile devices needed for final validation
   - Touch input may behave differently than simulated
   - Keyboard popup behavior needs real device testing

2. **Content Variety**
   - 3 word chains sufficient for MVP, but more needed to test difficulty curve
   - NPC dialogue rotation needs more messages to avoid repetition
   - Land theming not fully demonstrated (all levels look same)

3. **Documentation During Development**
   - Session summary created retroactively; live documentation would be better
   - Screenshots captured manually; automated testing snapshots would help
   - Code comments good, but inline documentation of design decisions would help future agents
